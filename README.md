# 共时招标雷达

给河南信育电子科技、深圳共时科技的商务同事用的公开招标公告筛选页。打开就能按产品线、地区、学段、公告类型、预算和截止日期缩小范围，也可以把同一组筛选结果用链接发给同事。

页面地址保持不变：<https://aresccxk-boop.github.io/tender-radar/>

页头是「共时招标雷达」，页脚是「深圳共时科技 · 数字员工团队出品」。仓库是公开的，里面没有账号和密钥。

## 怎么用

桌面浏览器打开上面的地址。左侧是筛选，右侧是表格。

- 点表头的「发布」「截止」「预算」可以排序。空日期和空金额会排在最后。
- 筛选条件写在地址栏里。复制链接发给同事，打开就是同一组结果。工具栏也有「复制链接」。
- 「导出 Excel」下载的是 Excel 能直接打开的表格，「导出 CSV」是 UTF-8 带 BOM 的逗号文件。导出的是当前筛选的全部结果，不只是这一页。
- 勾选公告后点「复制摘要」，得到一段可直接贴到企业微信的纯文字，包含标题、采购单位、预算、截止日期和原文链接。有成交供应商时会一并写上。
- 「打印 / PDF」按当前筛选打出全部清单，用浏览器的「另存为 PDF」即可。
- 截止日 3 天内用红色标出，7 天内用橙色标出，已经过去的日期变灰。
- 四个常用视图：「本周截止」「河南新公告」「广州 AI 实验室」「中标结果」。
- 手机上可以点右上角「筛选」打开同一组条件，表格可以横向滑动。

预算和截止日期来自公告正文，有的公告本身没写，表格里就是「—」。

## 数据源

只抓公开页面，不登录，不碰付费平台。每次请求至少间隔 1.5 秒。某个源失败不会让整次更新失败，页面顶栏用颜色标出各源状态：绿是成功，黄是只抓到一部分，红是这次没抓到。把鼠标放在状态上可以看到原因。

下面是在境外网络（和 GitHub 托管 Runner 同类出口）上的实测。GitHub Actions 的定时任务要等这个工作流进入默认分支后才会按点跑，所以「Actions 上」的结论来自同类型境外网络的实抓，不是猜测。

| 来源 | 境外 / Actions | 页面上怎么用 |
|---|---|---|
| 广东省公共资源交易平台 `ygp.gdzwfw.gov.cn` | 可用。公开搜索接口能打开，详情里能补到预算、截止日、采购人。广州各区也在这里。 | 入库，地区记为广州或广东其他 |
| 全国公共资源交易平台 `ggzy.gov.cn` | 可用。政府采购检索接口本次没有要求验证码，正文页里有原文链接。中国政府采购网从境外打不开，全国公告改由这里补充。 | 入库。河南、广东的公告会归到对应地区，其余算全国 |
| 河南省政府采购网 `zfcg.henan.gov.cn` | 不稳定。首页和部分列表有时能开，有时握手超时。代码会按栏目跳过失败的列表，已经抓到的保留。国内机器上更稳，用下面的本地脚本补。 | 能抓到就入库，抓不到就靠全国平台里的河南公告顶上 |

GitHub Actions 的定时任务要等这个工作流进入默认分支后才会按点执行。上面的可达性是在和托管 Runner 同类的境外网络上测的。

中标、成交、合同公告会归到「结果中标」，用来看成交价和供应商。采购意向、招标/磋商/谈判/询价、更正公告分开筛选。

## 自动更新

GitHub Actions 在北京时间每天 **7:30** 和 **13:30** 跑 `scripts/fetch.py`，把 `data/tenders.json` 提交回仓库。页面只读这个文件和 `config/rules.json`，不需要服务器。

对应的 UTC 时刻是前一天 23:30 和当天 05:30，写在 `.github/workflows/fetch.yml`。中国没有夏令时。也可以在 Actions 页面手动点 “Run workflow”。

定时任务只在默认分支上的工作流生效。合并之后才会开始每天跑。

脚本会把新抓到的公告和文件里已有的公告合并，并丢掉发布日期早于「保留天数」的记录，避免文件无限变大。某个源这次失败时，上次已经入库的公告还留着。

## 国内机器补抓

政府网站对境外 IP 不稳定时，在国内电脑上执行：

```bash
bash scripts/fetch_and_push.sh
```

脚本会建虚拟环境、安装依赖、抓取，并只提交 `data/tenders.json` 再推送。这台电脑需要已经能 `git push` 这个仓库。推上去之后，等 Pages 刷新，同事刷新网页即可。

只想看规则有没有写错、不访问网站：

```bash
python3 scripts/fetch.py --check
```

只重抓某一个源（`gd`、`henan`、`ggzy`、`ccgp`、`gdgpo`、`gzggzy`）：

```bash
python3 scripts/fetch.py --only henan
```

`--only` 会把这次结果合并进已有的 `data/tenders.json`，并更新对应来源的状态，不会清掉其他来源已经抓到的公告。

## 改关键词和分类

非开发同事只改 [`config/rules.json`](config/rules.json)，保存后分两种效果：

1. **产品线、学段、公告类型、河南地市**：网页每次打开都会读这个文件，改完推送到仓库（或 Pages 更新后）刷新即可，不用重新抓取。
2. **搜索关键词、排除词、抓取页数**：只影响下一次抓取。改完要等定时任务，或自己跑 `scripts/fetch.py`。

字段说明：

| 字段 | 作用 |
|---|---|
| `搜索关键词` | 抓取时拿去搜索的词。标题里必须完整出现才会留下，避免「创新」这类被拆开的模糊结果。 |
| `关键词还需包含` | 某个搜索词太宽时，标题里还要出现其中任意一个词。例如「传感器」必须同时像实验室或教学场景。 |
| `排除词` | 标题里出现就丢掉，用来挡物业、食堂这类误伤。 |
| `产品线` | 筛选项。按顺序匹配标题，可以同时属于多条产品线；一条都对不上就是「其他」。 |
| `学段` | 按顺序匹配标题和采购单位，先匹配到的为准。所以「职业技术学院」要写在「学院」前面，否则会被当成大学。只写了「中学」、分不出初中高中的，筛选初中或高中时也会出现。 |
| `公告类型` | 按顺序看标题和来源里的原始类型。意向、更正、结果要写在「招标公告」前面。 |
| `河南地市` | 从标题和采购单位里认地市，供左侧「河南地市」筛选。 |
| `区县归属` | 县、县级市归到哪个地市。例如「禹州」归「许昌」，这样筛许昌时不会漏掉禹州的学校。 |
| `重点省份` | 全国平台额外按省份再搜一遍的行政区划代码。`410000` 是河南，`440000` 是广东（含广州）。全国结果太多时，这两个省不会被挤出前两页。 |
| `抓取.每个关键词页数` | 广东和全国每个词翻几页。 |
| `抓取.河南每个栏目页数` | 河南每个栏目（意向、采购公告、更正、结果）翻几页，省级和市县都会翻。 |
| `抓取.请求间隔秒` | 两次请求的最小间隔，不能小于 1.5。 |
| `抓取.详情上限` | 每次最多给多少条公告补开正文（预算、截止日、供应商）。 |
| `抓取.全国时间范围` | 全国平台的时间窗，`04` 是近一月。 |
| `抓取.保留天数` | 发布日期早于这么多天的旧公告会从文件里去掉。 |

改完可以用 `python3 scripts/fetch.py --check` 确认文件还是合法的 JSON，并且关键词规则能跑通。
